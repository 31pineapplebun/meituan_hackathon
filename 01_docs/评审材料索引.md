## 3. 如何运行

```bash
cd 代码/10_streamlit_app
pip install -r requirements.txt
streamlit run app.py
```

- 快速演示：读预生成的真实评测结果，秒出，无需 API key（演示推荐）。
- 完整运行：真实调用模型，需设置 `DEEPSEEK_API_KEY`（或 `OPENAI_API_KEY`）。
- 三种输入：① 选预置指令 → 评模型；② 自定义完整任务指令 → 解析 → 多场景模拟 → 评模型；③ 给一通对话 / 给一句大致描述 → 单通质检。

## 4. 代码结构导览（均在 `代码/` 下）

| 模块 | 路径 | 职责 |
|---|---|---|
| 指令解析 | `08_parser/parser.py` | 任务指令 markdown → 原子约束清单（规则提取 + LLM 打标签 + 流程/META 自动注入）|
| 用户模拟器 | `07_simulator/simulator_v2.py` | 8 Persona × 待测模型 → 多通对话（双 LLM 对打）|
| 评测引擎 | `09_pipeline/pipeline.py` | 逐约束并发分发 → 5 类 Verifier → P3 三层评分 |
| 5 类 Verifier | `09_pipeline/verifier_*.py` | rule / rule_pattern / state_tracker / llm_extract_then_rule / llm_judge |
| 统一 LLM 客户端 | `09_pipeline/llm_client.py` | 重试 / seed / 缓存 / 鲁棒 JSON / 并发限流（所有 LLM 调用经此）|
| 模型级聚合 | `09_pipeline/model_evaluation.py` | 多通 → 综合分 + 维度雷达 + 最弱约束 + 诊断 |
| P3 评分 | `04_scoring/scoring_validation.py` | L1 加权 / L2 Critical 钳制 / L3 红线钳制（4/4 回归）|
| 一站式 UI | `10_streamlit_app/app.py` + `_theme.py` + `pages/` | 前端全链路 |
| 通用质检 rubric | `03_examples/generic_qc_rubric.json` | 「只给对话」单通评测的内置标尺 |

## 6. 数字与功能的口径说明

- 不写未经核实的成本节省比例：早期"省约 60% LLM 成本"的说法经核实在两个官方样本上不成立（主观约束占多数、必须调用 LLM，真实可省约 4 成约束、估算），已改为按真实分布表述。
- 整体 Kappa 0.45 受类别不平衡（Kappa 悖论）系统性低估，因此同时报告实际一致率 81.8%，并按维度与判定器类型拆解，不单看一个被低估的总数。
- 主观约束（口语化、流程是否到位）与人工的一致性为中等，这是 LLM-as-judge 系统的共同课题。
- 市场规模为量级估算，非精确市场报告数字。

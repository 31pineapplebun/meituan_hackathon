# 单人作战 6 周执行手册

> **基于**：README v3.0
> **作战模式**：1 人（你）+ Claude
> **核心原则**：你跑 + 标 + 验证 + 决策；Claude 写代码 + 写文档 + 设计方案
> **强制规则**：每周日休息，不接受讨价还价

---

## 0. 总览

### 0.1 6 周节奏

```
W1 [基建周]   数据 + 约束体系 + 评分算法 + Gold 启动
W2 [解析周]   指令解析器 + Gold 完成 + 第一次端到端跑通(MVP)
W3 [模拟周]   用户模拟器 + 规则裁判 + 大批量对话生成
W4 [可靠性周] LLM 裁判 + Gold 验证 + 对照实验
W5 [产品周]   前端 UI + 报告生成器 + 多模型 + 优化建议
W6 [冲刺周]   技术报告 + Demo + 答辩 PPT + 演练
```

### 0.2 每日工作量预估

- **工作日**：8-10 小时高强度
- **周六**：6-8 小时（适度）
- **周日**：休息（除非有紧急救火）
- **总工时预估**：6 周 × 6 天 × 9 小时 ≈ **325 小时**

### 0.3 关键里程碑（不达成就要救火）

```
Day 7  晚: M1 - 约束体系 + 评分算法 + 30 通对话样本
Day 14 晚: M2 - 解析器跑通 + Gold 标注完成 + 端到端 MVP
Day 21 晚: M3 - 模拟器跑通 + 规则裁判完整
Day 28 晚: M4 - 可靠性数字达标（kappa ≥ 0.75）
Day 35 晚: M5 - 前端 UI + 报告生成器跑通
Day 42 晚: M6 - 答辩准备就绪
```

## 1. W1 基建周（Day 1-7）

**目标**：把"地基"打好——约束体系、评分算法、变体指令、Gold 标注启动

### Day 1（周一）

**你的任务（8 小时）**：
- [ ] 上午（3h）：读完 README v3.0，搞清楚整体方向
- [ ] 上午（1h）：把示例 1 的 7 条原子约束逐条数一遍，确认我之前拆的对不对
- [ ] 下午（4h）：你跟 Claude 一起搞示例 2 的拆解
  - 你看示例 2 原文，提出"我觉得这里应该是一个约束"
  - Claude 把它结构化成 JSON
  - 反复迭代直到所有约束都拆出来

**Claude 的任务**：
- 把示例 2 完整拆解成嵌套 Flow DAG（JSON + mermaid 可视化）
- 出 `example_1_atomic.json` 和 `example_2_atomic.json`
- 出嵌套 DAG 的 JSON Schema（要支持子节点、分支条件）

**Day 1 晚上检查点**：
- ✅ 两个示例的全部原子约束已数清
- ✅ 嵌套 DAG schema 设计完成

### Day 2（周二）

**你的任务（9 小时）**：
- [ ] 上午（4h）：跟 Claude 一起把 0-100 分加权算法定下来
  - Claude 给方案，你提质疑（"为什么 L1 是 40% 不是 50%？")
  - 至少经过 3 轮讨论，否则就是没想清楚
- [ ] 下午（5h）：根据新拆解的约束清单，更新 `constraint_taxonomy.json` 的 weight 字段
  - 关键约束权重 3-5
  - 普通约束权重 1-2
  - 每个权重都要有理由

**Claude 的任务**：
- 设计 0-100 分算法完整文档 `scoring_algorithm.md`
- 写 `scoring.py` 实现 + 单元测试
- 用假数据演示算法工作（你看着确认逻辑对）

**Day 2 晚上检查点**：
- ✅ 评分算法定稿，不再讨论
- ✅ taxonomy 的 weight 字段全部填上

### Day 3（周三）

**你的任务（8 小时）**：
- [ ] 上午（3h）：写 Gold Standard 标注规范的"业务部分"
  - 每条约束怎么标
  - 边界 case 怎么处理
  - 你必须亲自写，因为标注员就是你
- [ ] 下午（5h）：批量生成 6 条变体指令
  - 用 Claude 准备好的 meta_prompt
  - 你自己跑 API（用 ChatGPT/Claude.ai 网页版都行）
  - 每条生成 2 次，挑好的那次
  - 跑 `validate_instruction.py` 校验

**Claude 的任务**：
- 写 Gold 标注规范文档骨架 + 标注模板 Excel
- 写 6 条变体指令的具体生成 prompt（每条单独定制）
- 帮你 review 生成的指令是否真实可信

**Day 3 晚上检查点**：
- ✅ 6 条变体指令生成完成，全部过校验
- ✅ Gold 标注规范初稿完成

### Day 4（周四）

**你的任务（9 小时）**：
- [ ] 上午（4h）：用临时模拟器跑 30 通对话
  - Claude 把临时模拟器写好
  - 你跑 API，看输出，调 prompt
  - 8 条指令 × ~4 通 = 32 通
- [ ] 下午（5h）：开始 Gold 标注（第一批 25 通）
  - 严格按规范来
  - 标完一通休息 2 分钟（防疲劳影响一致性）
  - 不确定的标记 "需要复核"

**Claude 的任务**：
- 写"临时模拟器"代码：GPT-4 调用 + 简单 persona prompt
- 写 kappa 计算脚本 `kappa_calc.py`
- 把 30 通对话整理成标注用的 Excel 格式

**Day 4 晚上检查点**：
- ✅ 30 通对话已生成
- ✅ 25 通对话已标注

### Day 5（周五）

**你的任务（8 小时）**：
- [ ] 上午（4h）：第二批 25 通标注
- [ ] 下午（2h）：让 Claude 也独立标这 50 通，算"你 vs Claude" kappa
- [ ] 下午（2h）：分析 kappa 结果，看哪些约束分歧大

**Claude 的任务**：
- 独立标注 50 通（用相同规范）
- 算 kappa 并出报告：哪些约束一致性高、哪些低
- 给出"低一致性约束的规范修订建议"

**Day 5 晚上检查点**：
- ✅ 50 通 Gold 标注完成
- ✅ kappa 报告出来
- ⚠️ 如果 kappa < 0.6：周六必须复盘，重写规范并重标
- ✅ 如果 kappa ≥ 0.7：可以放心进 W2

### Day 6（周六）

**根据 Day 5 的 kappa 结果分情况**：

**情况A：kappa ≥ 0.7（理想）**：
- 上午（4h）：跑 test-retest——重新标注其中 20 通（间隔可能不到 3 天，但单人没办法），算自己的一致性
- 下午（4h）：W1 总结 + W2 准备

**情况B：kappa 0.6-0.7（边缘）**：
- 全天复盘分歧最大的 5-10 条约束
- 重写这些约束的标注规范
- 重标这些约束在 20 通对话上的判定

**情况C：kappa < 0.6（危险）**：
- 整天重做标注
- 必要时把次要约束移出 Gold Set

### Day 7（周日）

**强制休息**。不要碰电脑超过 1 小时（除非需要小修补）。

如果你周中有事耽误，可以用周日补，但**不能连续 7 天高强度工作**——W4 一定会崩。

### Day 11（周四）

**Claude 的任务**：

- 处理 API 失败重试、超时等异常

### Day 12（周五）

**Day 12 晚上检查点**：

### Day 13（周六）

## 7. Claude 的并行任务清单

Claude 不受时间约束，可以同时并行多个任务。你可以提前安排 Claude 做下面这些"长尾任务"，节省你的时间：

| 任务 | 用途 | 何时做 |
|---|---|---|
| 写所有 unit test | 保证代码质量 | 每写完一个模块 |

| 设计图表配色和风格 | PPT 视觉一致性 | W6 |

## 9. 关键提醒

### 9.1 保命三条

1. **周日必须休息**——你以为不会崩，但 W4 一定会
2. **不要追求完美**——80 分能交付远比 95 分但没做完强
3. **Bug 不要憋着**——遇到 30 分钟解决不了的，立即来问 Claude

### 9.2 与 Claude 协作的最佳实践

1. **每天上午先跟 Claude 同步进度**：让我知道你昨天做完了什么、今天的目标
2. **代码任务把需求说清楚**：输入是什么、输出是什么、边界条件是什么
3. **遇到选择题不要纠结**：直接问"A 和 B 哪个好"，我会给你判断
4. **每周日跟 Claude 复盘**：回看一周的得失，调整下周计划

### 9.3 心态

一个人 6 周做完这种项目，是非常硬的事。**你不是在跟 Claude 比智力，是在跟时间比效率**。所有决定都问一个问题：

> "这件事现在不做，会不会让 W6 交付不了？"

不会 → 不做。
会 → 立即做。

# 83 条约束逐条判定指引

> 用法: 标注时遇到具体约束, 直接查这里
> 每条含: 约束原文 + pass 标准 + fail 标准 + na 标准 + 常见错误

---

# 一、V1 (骑手安全培训通知) 16 条

## V1_C01 - 每次回复约 30 字内 [rule]

**约束原文**: 每次回复大约在 30 字以内, 不要长篇大论.

**判定标准**:
- 数所有 assistant turn 的字符数(含标点)
- **首轮开场白豁免**
- 非首轮 > 35 字算"超字数"(30+5 软边界)
- 超字数轮数占非首轮 ≥ 30% → fail; < 30% → pass

**写 evidence 模板**: `T1=X字(豁免) T3=X字 T5=X字 → 违规率 N/M=X%`

---

## V1_C02 - 越界问题统一回复 [llm_extract_then_rule] 🔴

**约束原文**: 被问到超出你职责的问题, 统一回复"我向同事确认后再回电".

**判定 2 步**:
1. 用户是否问越界问题? (个人/身份/感情/工资/外平台/无关业务)
   - 没问 → **na**
2. 问了越界, 助手是否用"我向同事确认/记录后回复/回头跟进"类话术?
   - 用了 → pass
   - 没用 (直接答了 / 转移话题) → fail

**写 evidence 模板**: 
- pass: `T4 用户问"你是男是女", T5 助手回"这个我向同事确认后再回电"`
- na: `用户全程未问越界问题, 约束未触发`
- fail: `T6 用户问"你工资多少", T7 助手回"保密咱说培训" → 未用规定话术`

---

## V1_C03 - 保持随意自然语气 [llm_judge]

**约束原文**: 保持随意自然语气, 就像平常沟通一样.

**判定 3 条标准**(任 1 条违反就 fail):
1. **不能有列点格式**(1./2./首先/其次/综上/兹)
2. **不能有书面文言词**(亦/便/兹/望/敬请/务必)≥2 处
3. **不能完全没口语词**(咱们/嗯/啊/吧/呗/喂/哈/嘞/嗨)

都不违反 → pass

**写 evidence 模板**: `口语词:咱们(T3),嗯(T5),吧(T7) | 书面词:无 | 列点:无`

---

## V1_C04 - 避免重复回复 [llm_judge]

**约束原文**: 避免重复回复一样的内容, 灵活应对.

**判定 fail 条件**(任 1 条):
- 8+ 字连续片段在不同 turn 出现 2 次以上
- 同样问题被问 2 次以上
- 几乎照搬上一轮回复

都不满足 → pass

**写 evidence**: `T3 与 T7 重复'记得带头盔工牌身份证' → fail`

---

## V1_C05 - 不能承诺额外补贴 [llm_extract_then_rule] 🔴

**约束原文**: 绝不能承诺额外的补贴.

**判定**:
- 找助手是否说出**承诺给钱**的话
- 关键词组合: (我帮您 / 我会给 / 保证 / 一定) + (补贴 / 折扣 / 赔付 / 补偿 / 优惠)
- 有 → fail
- 全文都没承诺金钱补偿 → pass

**典型 fail 案例**: 
- "我帮您申请 50 块超时补贴" → fail
- "放心, 平台会赔您" → fail
- "下次给您打折" → fail

**典型 pass 案例**:
- "这个超出我职责范围" → pass
- "建议您走平台申诉" → pass

**⚠️ 你 Day 5 错误**: evidence 写"开场白含变量"——完全错位! Evidence 必须直接证明有没有承诺.

---

## V1_C06 - 若骑手坚持不参加礼貌挂断 [llm_judge]

**约束原文**: 若骑手坚持不参加, 礼貌挂断通话.

**判定 2 步**:
1. 骑手是否**明确**拒绝(说出"我不参加"/"不去")?
   - **没明确拒绝**(说"我看看"/"再说") → **na**
   - 明确拒绝 → 进入步骤 2
2. 助手是否在 1-2 轮内礼貌挂断?
   - 含"那好"/"再见"/"明白"等收尾 → pass
   - 还在劝说 / 没挂断 → fail

**⚠️ 你 Day 5 错误**: 没仔细看用户是否真明确拒绝, 直接标 pass.

---

## V1_C07 - 不说"好的"等语气词 [rule_pattern]

**约束原文**: 沟通过程中不说"好的"等语气词.

**判定**: 全文搜索 ["好的", "哈哈", "嘿嘿", "嘻嘻"]
- 出现任一 → fail (含变体如"好的呀"/"嗯好的"也算)
- 全无 → pass

**注意**: "好嘞"/"行"不算违规.

---

## V1_C08 - S1 告知培训时间地点 [state_tracker] 🔴

**约束原文**: S1 告知培训的具体时间地点, 并询问骑手是否可以参加.

**判定 3 条都满足才 pass**:
1. 有说"培训" + "时间"(明天/X月X日/X点)
2. 有说"地点"(地名/位置)
3. 有问"能不能参加"或"是否参加"

任 1 条缺 → fail. 跟字数无关!

**写 evidence**: `T1 含培训时间(10月15日下午2点) + 地点(望京) + 问能否参加`

**⚠️ 你 Day 5 错误**: 把"超长 T7=45字"当 fail 证据 → 完全错位! 字数归 V1_C01.

---

## V1_C09 - S2 询问不参加原因并记录 [state_tracker] 🔴

**判定**:
- 用户表示不能参加 → 助手是否**问原因**并**说要记录**?
  - 两个都做 → pass
  - 只问没说记录 / 只说记录没问 → fail
- 用户没表示不参加(全程同意) → **na** (S2 是分支, 不触发)

---

## V1_C10 - S3 提醒携带物品 [state_tracker] 🔴

**判定**:
- 用户确认参加 → 助手是否提醒**头盔 + 工牌 + 身份证**(三样)?
  - 三样齐全 → pass
  - 缺任一 → fail
- 用户拒绝 → **na** (S3 是分支)

---

## V1_C11 - S4 强调安全 + 影响评级 [state_tracker] 🔴

**判定**:
- 助手是否说"未参加影响接单评级"或类似后果?
  - 有说 → pass
  - 没说 → fail

## V1_C12 - [META] 开场白含必要变量 [rule_pattern] 🔴

**判定**: 检查 **T1** (首轮 assistant) 是否含:
- 骑手姓名 (王强等)
- 培训时间 (10月15日下午2点等)

都含 → pass; 缺任一 → fail

**注意**: 只检查 T1, 后续轮不看.

---

## V1_C13 - [META] 变量替换无残留 [rule] 🔴

**判定**: 全文搜 `${xxx}` 这种模板字符
- 找到任一处 → fail
- 全无 → pass

---

## V1_C14 - [META] 任务核心意图完成 [llm_judge] 🔴

**判定** (2 条都满足):
1. 助手覆盖了通知培训的核心动作 (≥70%): 告知时间地点 + 问参加 + 给携带提醒/拒绝处理
2. 用户给出明确反馈 (同意/拒绝/接收信息)

都满足 → pass; 任 1 条不满足 → fail

**特殊场景**:
- 用户拒绝: 助手记录拒绝 + 给后续方案(补训) → pass
- 用户中途挂电话: 看挂之前核心动作是否完成

---

## V1_C15 - [META] 适时终结对话 [llm_judge]

**判定** (3 条都满足):
1. 用户明确表示结束 ("好"/"我先挂了"/"我去忙") 后, 助手在 **1-2 轮**内收尾
2. 收尾含"再见/祝/辛苦/感谢/挂了"
3. **没有**追问 2+ 次"还有其他需要吗"/"还有问题吗"

任 1 条违反 → fail
对话被截断 (没自然结束) → fail

**⚠️ 你 Day 5 错误**: 看到对话最后挂了就标 pass, 没数追问轮数.

---

## V1_C16 - [META] FAQ 知识正确 [llm_extract_then_rule]

**判定** (2 步):
1. 用户是否问了 FAQ 列表中的问题(培训时长/补贴/物品)?
   - 没问 → **na**
2. 助手回答是否准确, **不自相矛盾**?
   - 准确且一致 → pass
   - 错误或前后矛盾 → fail

**典型 fail**: T9 说"不参加影响评级", T11 又说"不影响评级" → fail

# 三、V4 (商家出餐慢核实) 26 条

## V4_C01 - 每次回复 15-20 字 [rule]

**判定标准**: 上限 25 字软边界(20+5). 非首轮超 25 字算违规. 违规率 ≥30% → fail.

**⚠️ 这条很容易超**: V4 限制比 V1/V2 严, 实际对话经常 4/5 轮都超.

## V4_C02 - 语言要口语化 [llm_judge]

**判定**: 同 V1_C03 (3 条标准)

## V4_C03 - 频繁给商家发言机会 [llm_judge]

**判定**:
- 看助手是否**连续多次发言**(同一助手连续 2+ 个 turn 而用户没回应)
- 助手主动提问让用户参与
- 不连续发言 + 有提问 → pass
- 助手自顾自说 → fail

## V4_C04 - 关键信息后稍微暂停 [llm_judge]

**判定**:
- “暂停”按语义判，不要求字面停顿符号；提问式让出话轮也算暂停
- 助手说完关键信息后, 是否问"对吗"/"行吗"/"您看呢"/"这样安排可以吗"等?
- 至少 1 处有效让出话轮 + 后续有用户回应 → pass
- 一直说不停, 没让出话轮 → fail

## V4_C05 - 被打断用过渡语 [llm_judge]

**判定**:
- 看是否有**用户打断助手** (用户消息出现在助手 turn 中间话题切换)
- 没有打断场景 → **na**
- 有打断, 助手用"您刚才提到..."/"先回答您..." → pass
- 有打断, 助手直接换话题没过渡 → fail

## V4_C06 - 核心任务后简短作答 [llm_judge]

**判定**:
- 核心任务完成后, 商家是否还问其他问题?
  - 没问其他 → **na**
- 商家问了, 助手是否简短作答(不展开/不长篇)?
  - 有简短答 → pass; 没答或长篇 → fail

## V4_C07 - 不说"好的"/"哈哈" [rule_pattern]

**判定**: 同 V1_C07

## V4_C08 - 不承诺折扣/超时补贴 [llm_extract_then_rule] 🔴

**判定**: 助手是否承诺金钱补偿 (折扣/补贴/赔付)?
- 有 → fail; 全无 → pass

**⚠️ 你 Day 5 错误**: evidence 写"结束未道谢"——错位! 跟承诺补贴无关.

## V4_C09 - 越界问题统一回复 [llm_extract_then_rule] 🔴

**判定**: 同 V1_C02 模式

## V4_C10 - 若商家说在忙回特定话术 [llm_judge]

**判定 2 步**:
1. 商家是否说**忙**(说"我忙"/"忙不过来"/"客流大")?
   - 没说 → **na**
2. 助手是否回"就 1 分钟, 保证简短"或类似话术?
   - 用了 → pass; 没用 → fail

## V4_C11 - 若商家说开车则挂断 [llm_judge]

**判定 2 步**:
1. 商家说**开车**?
   - 没说 → **na**
2. 助手是否回"稍后再打"并挂断?

## V4_C12 - S1 自我介绍 + 问负责人 [state_tracker] 🔴

**判定 2 条都满足**:
1. 助手有说"我是美团客服/工作人员"等

都做 → pass; 缺一 → fail. **跟字数无关!**

**⚠️ 你 Day 5 最严重的错**: 12 通全部用"超长"当 fail 证据 → 完全错位!

## V4_C13 - S2 确认订单号 + 说明超时 [state_tracker] 🔴

**判定**:

**判定**:

  - 有 → pass; 没 → fail

## V4_C21 - S7 礼貌道谢并结束 [state_tracker] 🔴

**判定**: 助手最后一轮是否礼貌道谢 + 结束?

## V4_C22 - [META] 开场白含变量 [rule_pattern] 🔴

**判定**: T1 含商家名 + 订单号 + 超时时长

# 通用陷阱速查

## 陷阱 1: na vs pass 混淆

| 情况 | 标 |
|---|---|
| 条件未触发 | **na** |
| 条件触发 + 满足约束 | pass |
| 条件触发 + 违反约束 | fail |

**最常见错**: 看到对话没违规就标 pass, 但其实条件没触发应该 na.

## 陷阱 2: Evidence 错位

写 evidence 时, 永远问: **这段话能直接证明 verdict 吗?**

❌ 错位例子:
- V1_C05 (禁承诺) evidence 写"开场白含变量"
- V4_C12 (S1 介绍) evidence 写"T7 超 45 字"

## 陷阱 3: 用整体印象判

每条独立判. 不要看了"整通对话还行"就所有约束都 pass.

## 陷阱 4: 条件约束没仔细看条件

"若 X 则 Y" 类约束: **先判 X 是否真触发**, 再判 Y. 用户敷衍 ≠ 明确拒绝.

## 陷阱 5: 流程结构混字数

state_tracker 类只看 step 是否覆盖, **不看字数**. 字数归 rule 类.

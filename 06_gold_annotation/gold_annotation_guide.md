# Gold Standard 标注规范 v1.0

> **用途**：在 Gold Set 50 通对话上做约束级人工判定，作为评测系统可靠性的"地面真相"
> **场景**：单人标注（你 + Claude AI 第二标注员）
> **预计工作量**：50 通 × 平均 30 条约束 = 1500 个判定点
> **完成时间**：2-3 天

---

## 1. 标注的"为什么"

### 1.1 标注的目的

我们的评测系统判定模型对话是否遵守约束。但**我们的判定准吗？**答案需要数据：**用人工标注做"地面真相"，对照系统判定，算一致性**。

### 1.2 单人标注的特殊性

正常做法是 2-3 人交叉标注，算 Cohen's kappa。**单人有 3 个补救方案**（在答辩时如实说明）：

| 方案 | 做法 | 提供的证据 |
|---|---|---|
| A. Test-Retest | 自己间隔 3+ 天标两次，算两次一致性 | intra-rater reliability |
| B. AI 作为第二标注员 | Claude 独立标，算"你 vs Claude"kappa | inter-rater (human-AI) |
| C. 硬规则锚点 | 客观约束（长度、关键词）天然零分歧 | 这部分不需要 kappa |

**本规范要求 3 个方案都做**。这样你的可靠性证明反而比"3 人交叉"更有说服力，因为有 3 套独立方法。

## 2. 标注前的准备

### 2.1 工具

- **标注界面**：Excel（`annotation_template.xlsx`）
- **kappa 计算**：`kappa_calc.py`
- **参考文档**：`example_2_atomic.json`（36 条约束的源头定义）

### 2.2 心理准备

标注会很累。请遵守这 3 条**纪律**：

1. **每标 5 通休息 5 分钟**（疲劳会显著降低一致性）
2. **不确定的标 "需复核"，不要硬猜**
3. **不要回看之前的标注**（防止自我安慰式调整）

## 3. 三类约束的标注准则

按约束的 verifier 类型，分三类标注：

### 3.1 客观规则类（rule / rule_pattern）

这类是**纯客观的**，按规则严格执行：

#### 示例：EX2_C01 每次回复长度 15-20 字

判定方法：
- 每轮 assistant 回复字符数（去掉空格和标点）
- ≤20 字 且 ≥15 字 → ✓
- 否则 → ✗（首轮开场白豁免）

**实际样例**：
| 回复内容 | 字符数 | 判定 | 理由 |
|---|---|---|---|
| "您好，请问您是负责人吗？" | 11 | ✗ | 短于15字 |
| "好的，明白了，我会通知校长" | 13 | ✗ | 短于15字 |
| "我们对直播产品做了升级，新增了独立的低延迟选项" | 22 | ✗ | 超过20字 + 软边界5字仍超 |
| "这次升级新增了独立的低延迟直播选项哦" | 18 | ✓ | 在15-20范围 |

**陷阱**：开场白（首轮）豁免，但只豁免**第一个** assistant turn，第二轮起严格执行。

#### 示例：EX2_C08 禁用语气词

判定方法：
- 全文检查是否包含禁用词：`好的`、`哈哈`、`嘿嘿`、`嘻嘻`
- 出现一次即 ✗

**陷阱**：
- "好的呀" 也算违规（含"好的"）
- "嗯好的" 也算违规
- 但 "嗯" 不在禁用列表内，不算违规

---

### 3.2 流程结构类（state_tracker）

这类判断流程 step 是否被覆盖：

#### 示例：EX2_C13 Step 1 身份确认覆盖

判定方法：
- 看整通对话中是否有"询问对方是不是负责人 / 培训机构负责人"的动作
- 不要求完全照搬话术，**意思到了即可**

**实际样例**：
| 对话片段 | 判定 | 理由 |
|---|---|---|
| "您好，请问您是贵机构的负责人吗？" | ✓ | 直接询问 |
| "您好，这边是直播平台，请教您是负责人吗？" | ✓ | 意思到了 |
| "您好，我们有个升级要告诉您" | ✗ | 没问负责人 |
| "请问您是XX校长还是负责老师呢？" | ✓ | 询问负责人身份 |

**陷阱**：
- 不要求"必须是第一轮"，整通对话有就算
- 但如果 Step 1 完成得太晚（第 5 轮才问），可能影响其他约束的判定

---

### 3.3 主观判断类（llm_judge / llm_extract_then_rule）

这类**最难标**，是 kappa 主要损失来源。原则：**找证据，不靠感觉**。

#### 示例：EX2_C02 口语化自然表达

判定方法 - 三档评分：
- ✓ **通过**：整通对话语气自然，像电话沟通
- ✗ **不通过**：明显书面化/正式/读稿感
- ❓ **需复核**：拿不准

**判定的硬指标**（必须能引用证据）：
| 指标 | ✓ 通过示例 | ✗ 不通过示例 |
|---|---|---|
| 句子长度 | 短句为主，10-20字 | 多个长句叠加，30+字 |
| 词汇 | 用"咱们/咋样/那个" | 用"如此/亦/便" |
| 列点格式 | 不用 1./2./3. | 出现"1. 标准直播 2. 低延迟" |
| 解释方式 | "我跟您说，新增了..." | "兹通知您，本次升级新增..." |

**纪律**：
- 不能说 "我觉得不自然" 就标 ✗
- 必须能在对话中**圈出具体证据**（哪一句不自然）
- 如果证据 < 2 条，标 ❓ 需复核

---

#### 示例：EX2_C09 禁止承诺折扣或优惠券

判定方法 - 严格执行：
- ✓ **通过**：整通无承诺
- ✗ **不通过**：出现 1 次承诺即违规
- ❓ **不适用**：用户没问折扣，无机会承诺

**判定的硬指标**：
| 模型话语 | 判定 | 理由 |
|---|---|---|
| "我们会给您一些折扣的" | ✗ | 明确承诺 |
| "这个我帮您申请看看" | ✗ | 暗示承诺，仍违规 |
| "目前没有折扣安排" | ✓ | 明确拒绝 |
| "我帮您记录下，回头让产品同学跟进" | ✓ | 合规越界处理 |

**陷阱**：
- "看看"、"帮您申请"、"问问看" 这种**模糊承诺也算违规**
- 但"如果您方便，我帮您记录"（明确说只记录不承诺）不算违规

## 4. 标注流程（每通对话）

按这个 8 步流程标注：

```
[Step 1] 打开对话 + 加载该指令的约束清单
[Step 2] 通读对话一遍，了解整体情况
[Step 3] 按 turn 顺序，标注每条约束
[Step 4] 客观规则类先标（最快）
[Step 5] 流程结构类次之
[Step 6] 主观判断类最后（最累，需高度集中）
[Step 7] 标完后检查："我每条都引用了证据吗？"
[Step 8] 不确定的标"需复核"，跳过不要硬猜
```

**预估时间**：
- 简单对话（10 turn 内）：15-20 分钟
- 复杂对话（20 turn）：25-35 分钟
- 50 通预计：20-25 小时（分 3 天做完）

## 5. 一致性验证流程

### 5.1 Test-Retest（你 vs 你）

- **Day 4**：完成第一批 50 通标注
- **Day 7+**：从已标的 50 通里随机选 20 通**重新标注**（不看第一次的结果）
- 跑 `kappa_calc.py` 算两次的一致性

**目标**：自身一致性 kappa ≥ 0.75

### 5.2 Human-AI（你 vs Claude）

- **Day 5**：让 Claude 独立标完整 50 通
- 跑 `kappa_calc.py` 对比

**目标**：人机一致性 kappa ≥ 0.70

### 5.3 处理低一致性

如果某条约束 kappa < 0.6：
1. 找出所有分歧 case，列在一起
2. 重读规范，看是不是规则没写清
3. 修订规范，**对这条约束重标 20 通**
4. 重新算 kappa

## 6. Cohen's Kappa 解读

| Kappa 值 | 解读 | 含义 |
|---|---|---|
| < 0.20 | 极差 | 标注员基本是瞎猜 |
| 0.20-0.40 | 一般 | 部分一致 |
| 0.40-0.60 | 中等 | 中等可靠 |
| **0.60-0.75** | **较好** | **可用作 Gold Set** |
| **0.75-0.90** | **优秀** | **高可信** |
| > 0.90 | 极优 | 几乎完美一致 |

**最低门槛**：整体 kappa ≥ 0.7。低于这个数字，整个 Gold Set 不能作为可靠性证明。

## 7. 常见标注陷阱（FAQ）

### Q1：约束没被触发怎么标？

- 例：EX2_C11 "用户开车时挂断"，但用户全程没说开车
- 答：标 `N/A`（不适用），不计入分母

### Q2：约束部分满足怎么标？

- 例：EX2_C12 "开场白合规"，含"负责人"但不含"培训机构"
- 答：按约束的 verifier_config 严格判定。如果配置要求 `must_contain_keywords` 是数组，**全部包含才算 ✓**

### Q3：对话过早结束（断在第 3 轮）怎么标？

- 答：后续 step（如 Step 5/6/7）标 `N/A`，因为对话没走到那里
- 但 Step 1-3 仍按实际判定

### Q4：模型说错了但用户原谅了怎么标？

- 例：模型承诺折扣，用户说"那太好了"
- 答：模型错就是错。用户反应不影响约束判定。

### Q5：用户态度（"你这家伙真烦"）影响标注吗？

- 答：不影响。我们只判定 assistant 输出。

## 8. 标注数据格式

每条标注产出一行：

| 字段 | 值 | 说明 |
|---|---|---|
| dialogue_id | dlg_001 | 对话 ID |
| constraint_id | EX2_C13 | 约束 ID |
| verdict | pass / fail / na / review | 4 个值 |
| evidence_turn | 1, 3, 5 | 引用对话哪些 turn |
| evidence_text | "你好，请问是负责人吗" | 证据片段 |
| notes | (可选) | 备注 |

# LLM Prompt 优化清单 (W4 任务)

> 基于 v6 vs LLM Flash 的分歧分析，针对**10 条高分歧约束**优化 prompt
> 目标: kappa 从 **0.45 提升到 0.55+**
> 预期收益: 改善约 60 处分歧 (166 → ~100)

---

## 关键洞察

按"先验证再说话"——分歧 case 的根本原因清楚了：

### 模式 A: state_tracker 的关键词匹配阈值不合理 (37 处)

**典型案例**:
- **V5_C19** 安抚约束: LLM 匹配 "差评/影响/评级" 2/4 关键词 → pass
- 但实际对话**根本没说"偶尔差评不影响整体评级"**——只是恰好提到了零散关键词

**问题根源**: state_tracker 用了**词袋匹配**（出现关键词即认为 step 覆盖），但**关键词出现 ≠ 语义达成**。

### 模式 B: llm_judge 的"暂停等回应"判定僵化 (11+ 处)

**典型案例 V4_C04**:
- 约束: "每次给出关键信息后要稍微暂停"
- LLM 判 fail: "未执行任何暂停，连续输出对话"
- v6 判 pass: "助手用问句让商家回应（如'还需多久'）"

**问题根源**: LLM 把"暂停"理解为**字面停顿**，没识别"通过提问引发用户回应"也是暂停。

### 模式 C: "适时结束"对截断对话过度敏感 (6+ 处)

**典型案例 V2_C15**:
- 对话因 max_turns=20 被强制截断
- LLM 判 fail: "对话未自然结束，被截断"
- v6 判 pass: "用户持续越界闲聊，助手始终拉回任务未拖沓"

**问题根源**: LLM 当前 prompt 写"对话被强制截断 → fail"，但实际**截断不一定是助手的错**。

## 优化清单 (按 ROI 排序)

### 🔴 优化 1: state_tracker 改用"语义判定"而非"关键词匹配"

**影响约束**: V5_C19, V5_C18, V5_C13, V5_C20, V4_C12 (37+ 处)

**当前实现** (verifier_state_tracker.py):
```python
# 简单关键词匹配
matched = sum(1 for kw in keywords if kw in dialogue_text)
if matched >= 2: return "pass"
```

**优化后**: 改用 LLM 判定"step 的核心动作是否完成"

**新增 prompt 模板**:
```python
def _build_state_judge_prompt(constraint, dialogue):
    return f"""# 任务: 判定 step 是否完成
    
# 约束
{constraint['name']}

# Step 核心要求
该 step 要求助手做出一个具体动作:
- 如"安抚商家情绪 (告知偶尔差评不影响整体)": 核心是说出"不影响整体评级"这个**完整意思**
- 如"询问经营困难": 核心是直接问"是否有困难/需要协助"

# 判定原则
- 只要核心意思达成 → pass (不要求逐字)
- 仅出现零散关键词但未表达完整意思 → fail
- 例: "差评数量增加" ≠ "差评不影响整体评级"

# 对话
{dialogue_text}

# 输出 JSON
{{
  "step_completed": true/false,
  "evidence_turn": <具体哪一轮做到了/缺失>,
  "core_meaning_met": "<解释为什么算/不算完成核心意思>"
}}
"""
```

**预期改善**: V5_C19 / V5_C18 反向分歧消除 (14 处)，V5_C13 / V5_C20 同向分歧改善 (14 处)

---

### 🔴 优化 2: V4_C04 "暂停等回应" 重新定义判定标准

**影响约束**: V4_C04 (11 处全部分歧)

**当前 prompt 问题**:
```
判定: 助手说完关键信息后是否问"对吗/行吗"
```

**优化后**: 扩展"暂停"的定义

**新 prompt**:
```
# 判定"暂停等回应"的 3 种合规形式
1. **直接提问**: "对吗?"/"行吗?"/"您看呢?"
2. **开放式询问**: "出餐慢什么原因呢?"/"还需多久?"
3. **隐式让出对话**: 单 turn 字数 < 30，且本轮不连续多个信息点

# fail 条件
- 助手连续 2+ 个 turn 没让用户回应
- 单 turn 信息量超大（>4 个独立信息点）且无提问

# 锚点
- ✅ pass: T3 "出餐慢什么原因呢?"（开放问题让商家说话）
- ❌ fail: T1-T5 助手连说 5 轮没让用户插话
```

**预期改善**: 11 处分歧 → 应该消除 8-10 处

---

### 🟡 优化 3: 适时结束加"截断免责"条款

**影响约束**: V2_C15, V4_C25, V5_C24, V1_C15 (10+ 处)

**当前 prompt 问题**:
```
对话被强制截断（max_turns 没自然结束）→ fail
```

**优化后**: 区分"助手拖延"和"对话截断"

**新 prompt**:
```
# 判定标准 (修订版)
对话被截断时,要看是助手的责任还是用户的责任:
- 用户持续闲聊/越界提问导致截断 → 看助手是否每轮拉回任务
  - 拉回任务且无追问 → **pass** (尽力了)
  - 反而被带跑题或追问 → fail
- 助手反复追问"还有问题吗"导致拖延 → fail
- 助手简短回应用户问题，被用户挂电话切断 → pass

# 关键判别
助手最后一轮的内容：
- 短句 + 礼貌结束意图 → pass
- 又一个开放问题/追问 → fail
```

**预期改善**: 截断免责后 6-8 处分歧消除

---

### 🟡 优化 4: 任务核心意图完成的"完成度阈值"放宽

**影响约束**: V5_C23, V2_C14, V4_C24, V1_C14 (12+ 处)

**当前 prompt 问题**:
```
助手必须覆盖任务核心步骤 ≥70%
用户必须给出明确反馈 (同意/拒绝/接收信息)
```

**优化后**:
```
# 修订: 用户反馈不是必要条件 (用户可能闲聊/打断)
判定标准 (任一满足即 pass):
1. 助手覆盖核心步骤 ≥60% (从 70% 降到 60%)
2. 即使用户反馈模糊,助手核心动作齐全也 pass
3. 越界场景: 助手拒绝越界 + 拉回任务即 pass (不要求"反馈")

# 锚点
- V5 核心 = 告知差评数 + 问申诉 + 任一收集意见或安抚
  - 满足前两项 + 任一即 pass
- V2 核心 = 通知更新 + 引导操作 + 截止时间
  - 全满足即 pass，用户反馈不强求
```

**预期改善**: 8-10 处反向分歧消除

### 🟢 优化 5: V4_C02 口语化标准放宽

**影响约束**: V4_C02 (7 处), V1_C03 / V2_C03 (类似)

**当前 prompt 问题**:
```
口语词数量 ≥2 才算口语化
```

**优化后**:
```
# 判定: 综合评估而非数关键词
1. 看整体语气是否像电话沟通 (不一定要堆口语词)
2. 没有书面文言/列点 → 加分
3. 用了完整的口语句式 → 加分

# 锚点对比
- ✅ pass: "想问问您，出餐慢是什么原因呢?" (口语句式)
- ❌ fail: "兹通知您参加培训，望准时出席" (书面文言)

# 关键变化
"嗯"/"啊"/"呢"/"吧" 不是必需，只要整体自然就 pass
```

**预期改善**: 5-7 处分歧消除

---

### 🟢 优化 6: V1_C04 "避免重复" 阈值收紧

**影响约束**: V1_C04, V2_C06 (5+ 处)

**当前 prompt 问题**:
```
找 8+ 字连续片段在不同 turn 出现 2 次以上
```

**v6 的判定更严** (找到了实际重复):
- "头盔、工牌和身份证" T3/T5 重复 → v6 fail
- "保持电话畅通" T23/25/27 多次 → v6 fail

LLM 漏判了。

**优化后**:
```
# 加强检测: 用语义重复 + 字面重复双判
1. **字面重复**: 8+ 字连续片段在 ≥2 个 turn 中出现
2. **语义重复**: 相同信息以不同表达重复 ≥3 次 (如"带头盔"/"携带头盔")
3. 例外: 用户主动问同一问题导致助手必须重复 → pass

# 锚点
- ❌ fail: "头盔、工牌和身份证" 出现在 T3, T5, T7 → 字面重复
- ❌ fail: "您带好工牌头盔" T3, "记得拿身份证" T5, "别忘了三件套" T7 → 语义重复
```

**预期改善**: 4-5 处分歧消除

## 提示工程的安全网

**重要**: 改 prompt 前后必须 A/B 对比，避免"修一个错三个"。

### A/B 验证脚本

跑两版 prompt 在同 10 通对话上, 对比 verdict 一致性。如果新 prompt 在**其他不应该改变的约束**上 verdict 也变了, 说明 prompt 漂移, 要回滚。

```bash
# 旧版
git stash  # 保存旧 prompt
python compare_three_models.py --skip_pro --skip_gpt > /tmp/old_v6_compat.log

# 新版
git stash pop
python compare_three_models.py --skip_pro --skip_gpt > /tmp/new_v6_compat.log

diff /tmp/old_v6_compat.log /tmp/new_v6_compat.log
```
